# SNEAK'R Shop

เว็บขายรองเท้า Sneaker แยกเป็นหน้าบ้าน (frontend), หลังบ้าน (admin), และ backend API

## โครงสร้างโปรเจกต์

```
sneaker-shop/
├── backend/                 Express API server (Node.js)
│   ├── server.js
│   ├── db.js                ชั้นเชื่อมต่อฐานข้อมูลผ่าน libSQL (@libsql/client) — อ่าน/เขียนทุกตาราง
│   ├── package.json
│   ├── uploads/             รูปภาพสินค้าที่อัปโหลดจากหน้า admin
│   └── data/
│       └── sneakershop.db   ฐานข้อมูล SQLite สำรอง ใช้เฉพาะตอนรันในเครื่องตัวเอง (ไม่ commit ขึ้น git) — ตอน deploy จริงใช้ Turso แทน ดูหัวข้อ "ฐานข้อมูล" ด้านล่าง
├── frontend/                หน้าบ้าน (ร้านค้า)
│   ├── index.html           รายการสินค้า + Flash Sale + กรองแบรนด์/ช่วงราคา
│   ├── cart.html            ตะกร้า + สั่งซื้อ
│   ├── css/style.css
│   └── js/{common,shop,cart}.js
└── admin/                   หลังบ้าน (จัดการร้าน) — ต้องล็อกอินก่อนใช้งาน
    ├── login.html           หน้าเข้าสู่ระบบ
    ├── index.html           แดชบอร์ด (สินค้า/Flash Sale/ออเดอร์/ลูกค้า/พนักงาน/สรุปยอดขาย)
    ├── css/admin.css
    └── js/{login,admin}.js
```

## ฐานข้อมูล

โปรเจกต์นี้ใช้ **libSQL** (`@libsql/client`) เป็นตัวเชื่อมต่อฐานข้อมูล ซึ่งรองรับทั้ง 2 โหมดโดยสลับกันอัตโนมัติผ่าน environment variable:

- **ไม่ได้ตั้งค่า `TURSO_DATABASE_URL`** (เช่นตอนรันในเครื่องตัวเอง) → ใช้ไฟล์ `backend/data/sneakershop.db` ในเครื่องโดยอัตโนมัติ
- **ตั้งค่า `TURSO_DATABASE_URL` + `TURSO_AUTH_TOKEN`** (ตอน deploy จริง) → เชื่อมต่อไปยังฐานข้อมูล [Turso](https://turso.tech) แบบ hosted แทน

**ทำไมต้องใช้ Turso ตอน deploy จริง:** แพลตฟอร์ม deploy ฟรีหลายเจ้า (เช่น Render แผน Free) ไม่รองรับ persistent disk — พื้นที่เก็บไฟล์ในเครื่องเป็นแบบชั่วคราว (ephemeral) จะถูกล้างทุกครั้งที่ container รีสตาร์ท (deploy ใหม่ หรือเครื่อง "หลับ" แล้วตื่นขึ้นมาใหม่หลังไม่มีคนเข้าใช้สักพัก) ถ้าใช้ไฟล์ SQLite ในเครื่องตรง ๆ ข้อมูลจะหายไปทุกครั้ง Turso เป็นฐานข้อมูล SQLite แบบ hosted ที่อยู่แยกจากตัวเซิร์ฟเวอร์เว็บโดยสิ้นเชิง จึงไม่หายไปพร้อมกับ container

**วิธีตั้งค่า Turso (ทำครั้งเดียว):**

1. สมัคร/login ที่ [turso.tech](https://turso.tech) (ใช้ GitHub login ได้)
2. สร้างฐานข้อมูลใหม่ 1 ตัว (จากหน้าเว็บหรือ CLI ก็ได้) — แผนฟรีให้พื้นที่เพียงพอสำหรับร้านขนาดนี้
3. คัดลอก **Database URL** (ขึ้นต้นด้วย `libsql://...`) และสร้าง **Auth Token**
4. เอาไปตั้งค่าเป็น environment variable บนแพลตฟอร์ม deploy (เช่น Render → Environment Variables):
   - `TURSO_DATABASE_URL` = URL ที่คัดลอกมา
   - `TURSO_AUTH_TOKEN` = token ที่สร้างไว้
5. Deploy/redeploy ใหม่อีกครั้ง เซิร์ฟเวอร์จะสร้างตารางทั้งหมดในฐานข้อมูล Turso ให้อัตโนมัติตอนเริ่มทำงาน (เหมือนตอนใช้ไฟล์ในเครื่อง)

ไม่ต้องตั้งค่าตัวแปรทั้งสองนี้เลยตอนรันในเครื่องตัวเอง — ปล่อยว่างไว้ได้ ระบบจะ fallback ไปใช้ไฟล์ `.db` ในเครื่องให้อัตโนมัติ

## รูปภาพสินค้า

รูปสินค้าที่อัปโหลดจากหน้า admin ก็เจอปัญหาเดียวกับฐานข้อมูล — ถ้าเก็บไว้ในโฟลเดอร์ `backend/uploads/` ตรง ๆ บนแพลตฟอร์มที่ไม่มี persistent disk (เช่น Render แผน Free) ไฟล์รูปจะหายไปทุกครั้งที่ container รีสตาร์ท โปรเจกต์นี้จึงรองรับอัปโหลดขึ้น **[Cloudinary](https://cloudinary.com)** (บริการเก็บรูปภาพแบบ hosted ฟรี) แทน โดยสลับกันอัตโนมัติผ่าน environment variable เหมือนฐานข้อมูล:

- **ไม่ได้ตั้งค่า Cloudinary** (เช่นตอนรันในเครื่องตัวเอง) → เก็บไฟล์ไว้ในโฟลเดอร์ `backend/uploads/` ในเครื่องโดยอัตโนมัติ
- **ตั้งค่า `CLOUDINARY_CLOUD_NAME` + `CLOUDINARY_API_KEY` + `CLOUDINARY_API_SECRET`** (ตอน deploy จริง) → อัปโหลดขึ้น Cloudinary แทน ได้ URL ถาวรกลับมา

**วิธีตั้งค่า Cloudinary (ทำครั้งเดียว):**

1. สมัคร/login ที่ [cloudinary.com](https://cloudinary.com) (มีแผนฟรีให้พื้นที่เก็บรูปเพียงพอสำหรับร้านขนาดนี้)
2. เข้าหน้า **Dashboard** หลัง login จะเห็น **Cloud name**, **API Key**, **API Secret** อยู่ตรงนั้นเลย (ไม่ต้องสร้างอะไรเพิ่ม)
3. เอาไปตั้งค่าเป็น environment variable บนแพลตฟอร์ม deploy (เช่น Render → Environment Variables):
   - `CLOUDINARY_CLOUD_NAME` = Cloud name
   - `CLOUDINARY_API_KEY` = API Key
   - `CLOUDINARY_API_SECRET` = API Secret
4. Deploy/redeploy ใหม่อีกครั้ง รูปที่อัปโหลดจากนี้ไปจะขึ้น Cloudinary แทนอัตโนมัติ (รูปเก่าที่เคยอัปโหลดไว้ในเครื่องก่อนตั้งค่า จะไม่ถูกย้ายให้อัตโนมัติ ต้องอัปโหลดใหม่ผ่านหน้า admin)

ไม่ต้องตั้งค่าตัวแปรทั้งสามนี้เลยตอนรันในเครื่องตัวเอง — ปล่อยว่างไว้ได้ ระบบจะ fallback ไปเก็บไฟล์ในเครื่องให้อัตโนมัติ

## วิธีติดตั้งและรัน (เครื่องตัวเอง)

ต้องมี [Node.js](https://nodejs.org) (แนะนำ v18 ขึ้นไป) ติดตั้งในเครื่อง

```bash
cd sneaker-shop/backend
npm install
npm start
```

รันครั้งแรกจะสร้างฐานข้อมูลแบบว่างเปล่าให้อัตโนมัติ (ไม่มีข้อมูลตัวอย่างมาให้) จากนั้นกรอกข้อมูลจริง (สินค้า, พนักงาน ฯลฯ) ผ่านหน้า admin ได้เลย

เปิดเบราว์เซอร์ไปที่:

- หน้าร้านค้า (frontend): http://localhost:3000
- หลังบ้าน (admin): http://localhost:3000/admin — ต้องล็อกอินก่อน (ดูรหัสผ่าน default ด้านล่าง)

เซิร์ฟเวอร์ตัวเดียวทำหน้าที่เสิร์ฟทั้งไฟล์ static (frontend/admin) และ API พร้อมกัน จึงไม่ต้องตั้งค่า CORS หรือรันหลายพอร์ต

## ระบบล็อกอินหลังบ้าน

หน้า `/admin` ทั้งหมดถูกป้องกันด้วยระบบล็อกอิน (session + cookie) — ทุก API ที่แก้ไขข้อมูล (สินค้า, Flash Sale, พนักงาน, ลูกค้า, คำสั่งซื้อ) ต้องล็อกอินก่อนถึงจะเรียกใช้ได้ ส่วน API ที่หน้าร้านค้าใช้ (ดูสินค้า, ดู Flash Sale ที่ active, สั่งซื้อ) ยังเปิดสาธารณะตามปกติ

**ตั้งค่าชื่อผู้ใช้/รหัสผ่านผ่าน environment variable:**

| ตัวแปร | ค่า default (ถ้าไม่ตั้งค่า) | คำอธิบาย |
|--------|------------------------------|----------|
| `ADMIN_USERNAME` | `admin` | ชื่อผู้ใช้สำหรับล็อกอินหลังบ้าน |
| `ADMIN_PASSWORD` | `admin1234` | รหัสผ่านสำหรับล็อกอินหลังบ้าน |
| `SESSION_SECRET` | ค่าคงที่ในโค้ด (ไม่ปลอดภัยสำหรับ production) | กุญแจลับใช้เซ็นชื่อ cookie ของ session |

⚠️ **ค่า default ใช้ได้แค่ตอนทดสอบในเครื่องเท่านั้น** ก่อนขึ้นใช้งานจริงบนอินเทอร์เน็ต **ต้องตั้งค่าทั้ง 3 ตัวแปรนี้เอง** (ห้ามใช้ค่า default) ไม่งั้นใครก็เดารหัสผ่านเข้าหลังบ้านได้ ตัวอย่างการรันพร้อมตั้งค่า:

```bash
ADMIN_USERNAME=myshop ADMIN_PASSWORD="รหัสผ่านที่คาดเดายาก" SESSION_SECRET="สุ่มยาว ๆ ไม่ซ้ำใคร" npm start
```

หรือถ้า deploy บนแพลตฟอร์มคลาวด์ (Render, Railway, Fly.io ฯลฯ) ให้ตั้งค่าตัวแปรเหล่านี้ในหน้า **Environment Variables** ของแพลตฟอร์มนั้นแทน

## ระบบชำระเงิน

หน้าตะกร้าให้ลูกค้าเลือกวิธีชำระเงินได้ 3 แบบ: เก็บเงินปลายทาง, โอนผ่านธนาคาร, และพร้อมเพย์ (สร้าง QR code ตามยอดเงินอัตโนมัติ) หลังบ้าน (แท็บคำสั่งซื้อ) จะแสดงวิธีที่ลูกค้าเลือกไว้ให้เห็นด้วย

**ตั้งค่าบัญชีรับเงินผ่าน environment variable:**

| ตัวแปร | ค่า default (ถ้าไม่ตั้งค่า) | คำอธิบาย |
|--------|------------------------------|----------|
| `BANK_NAME` | `ธนาคารกสิกรไทย` | ชื่อธนาคารที่แสดงตอนลูกค้าเลือกโอนเงิน |
| `BANK_ACCOUNT_NUMBER` | (เลขบัญชีตัวอย่าง) | เลขบัญชีธนาคาร |
| `BANK_ACCOUNT_NAME` | (ชื่อบัญชีตัวอย่าง) | ชื่อเจ้าของบัญชี |
| `PROMPTPAY_ID` | (เบอร์โทรตัวอย่าง) | เบอร์โทร/เลขบัตรประชาชนที่ผูกพร้อมเพย์ ใช้สร้าง QR code |

⚠️ **ก่อนใช้งานจริงต้องตั้งค่าทั้ง 4 ตัวแปรนี้เป็นข้อมูลบัญชีจริงของร้าน** ไม่งั้นลูกค้าจะโอนเงินไปยังบัญชี/พร้อมเพย์ตัวอย่างที่ไม่ใช่ของร้านจริง

## ก่อนขึ้นออนไลน์ (deploy จริง)

โปรเจกต์นี้เป็น Express server ตัวเดียวที่เสิร์ฟทั้งหน้าบ้าน+หลังบ้าน+API ในตัวเดียวกัน (monolithic) วิธีที่ง่ายที่สุดคือ **deploy backend ตัวเดียว** แล้วให้มันเสิร์ฟทุกอย่าง ไม่ต้องแยก deploy frontend/backend คนละที่ก็ได้

**เช็คลิสต์ก่อน deploy:**

1. **ตั้งค่า `ADMIN_USERNAME`, `ADMIN_PASSWORD`, `SESSION_SECRET`** ผ่าน environment variable ของแพลตฟอร์ม deploy (ห้ามใช้ค่า default)
2. **ต้องใช้ HTTPS** เสมอ (แพลตฟอร์มคลาวด์ส่วนใหญ่ทำให้อัตโนมัติ) เพราะข้อมูลล็อกอิน/คำสั่งซื้อส่งผ่านเครือข่ายจริง
3. **ตั้งค่า `TURSO_DATABASE_URL` และ `TURSO_AUTH_TOKEN`** ให้ข้อมูลเก็บอยู่ถาวร ไม่หายเวลา container รีสตาร์ท/หลับแล้วตื่น ดูวิธีตั้งค่าในหัวข้อ "ฐานข้อมูล" ด้านบน — ถ้าลืมตั้งค่า ระบบจะ fallback ไปใช้ไฟล์ในเครื่องแทนแบบเงียบ ๆ (จะรันได้ปกติแต่ข้อมูลจะหายทุกครั้งที่ redeploy)
4. **ตั้งค่า `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`** ให้รูปสินค้าที่อัปโหลดเก็บอยู่ถาวรเช่นกัน ดูวิธีตั้งค่าในหัวข้อ "รูปภาพสินค้า" ด้านบน — ถ้าลืมตั้งค่า รูปจะยังอัปโหลดได้ปกติแต่จะหายทุกครั้งที่ container รีสตาร์ท (เหมือนปัญหาเดียวกับฐานข้อมูลถ้าไม่ตั้ง Turso)
5. รัน `npm install` (ไม่ใช่ `npm ci` ถ้าไม่มี lockfile ตรงกัน) บนเซิร์ฟเวอร์ปลายทาง แล้วสั่ง `npm start`
6. ตรวจสอบว่าพอร์ตที่แพลตฟอร์มกำหนดมาให้ถูกอ่านจาก `process.env.PORT` (โค้ดรองรับอยู่แล้ว)

**แพลตฟอร์มที่แนะนำสำหรับโปรเจกต์นี้**: แพลตฟอร์มฟรีอย่าง Render Free ใช้ได้เต็มรูปแบบแล้วตอนนี้ (ฐานข้อมูลอยู่ที่ Turso, รูปภาพอยู่ที่ Cloudinary ทั้งคู่แยกออกจาก container โดยสิ้นเชิง) ไม่ต้องพึ่ง persistent disk ของแพลตฟอร์มอีกต่อไป

## API หลัก

| Method | Endpoint | คำอธิบาย | ต้องล็อกอิน |
|--------|----------|----------|:---:|
| GET | `/api/products` | รายการสินค้าทั้งหมด | - |
| POST/PUT/DELETE | `/api/products` | จัดการสินค้า (รหัสสินค้าต้องไม่ซ้ำกัน) | ✅ |
| GET | `/api/flash-sales/active` | Flash Sale ที่กำลังลดราคาอยู่ (หน้าร้าน) | - |
| GET/POST/PUT/DELETE | `/api/flash-sales` | จัดการ Flash Sale ทั้งหมด | ✅ |
| POST | `/api/orders` | ลูกค้าสั่งซื้อจากตะกร้า (ระบุ `paymentMethod` ได้: `cod`/`bank_transfer`/`promptpay`) | - |
| GET | `/api/orders?date=` | ดูคำสั่งซื้อทั้งหมด (กรองตามวันที่ได้ ใช้ในสรุปยอดขายประจำวัน) | ✅ |
| PUT | `/api/orders/:id/status` | อัปเดตสถานะคำสั่งซื้อ | ✅ |
| DELETE | `/api/orders/:id` | ลบคำสั่งซื้อ (คืนสต็อกสินค้าที่เกี่ยวข้องกลับเป็นพร้อมขาย) | ✅ |
| GET | `/api/payment-info` | ข้อมูลบัญชีธนาคาร (สำหรับหน้าตะกร้า) | - |
| GET | `/api/payment/promptpay-qr?amount=` | สร้าง QR code พร้อมเพย์ตามยอดเงิน | - |
| GET/POST/PUT/DELETE | `/api/employees` | จัดการพนักงาน | ✅ |
| GET/POST/PUT/DELETE | `/api/customers` | จัดการฐานข้อมูลลูกค้า (แนบประวัติคำสั่งซื้อให้อัตโนมัติ) | ✅ |
| POST | `/api/upload` | อัปโหลดรูปสินค้า | ✅ |
| POST | `/api/auth/login` | เข้าสู่ระบบหลังบ้าน | - |
| POST | `/api/auth/logout` | ออกจากระบบ | - |
| GET | `/api/auth/me` | เช็คสถานะล็อกอินปัจจุบัน | - |

ข้อมูลทั้งหมดถูกเก็บผ่าน libSQL — ดูรายละเอียดที่หัวข้อ "ฐานข้อมูล" ด้านบน

## หมายเหตุ

- ตะกร้าสินค้าฝั่งลูกค้าเก็บไว้ใน `localStorage` ของเบราว์เซอร์ (ยังไม่มีระบบสมาชิก/login ฝั่งลูกค้า)
- ระบบล็อกอินหลังบ้านรองรับผู้ดูแลระบบคนเดียว (ชื่อผู้ใช้/รหัสผ่านชุดเดียวจาก environment variable) ไม่ได้ออกแบบมาสำหรับผู้ใช้หลายคนที่มีสิทธิ์ต่างกัน
